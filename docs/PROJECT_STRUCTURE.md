# Структура проекта CapriPet (C# / WPF)

В данном документе описана архитектура и структура каталогов приложения десктопного питомца-оверлея CapriPet на платформе C# (.NET 11 Windows Desktop) с использованием паттерна **MVVM (Model-View-ViewModel)**.

---

## Дерево каталогов

```text
CapriPet/
├── Assets/                        # Статические медиа-ресурсы
│   ├── Audio/                     # Звуковые эффекты (SFX) и файлы речи (WAV, MP3)
│   ├── Icons/                     # Иконки приложения и системного трея (.ico, .png)
│   └── Sprites/                   # Спрайты персонажа, кадры анимаций (PNG, GIF)
│
├── Commands/                      # Инфраструктура команд MVVM (ICommand)
│   └── RelayCommand.cs            # Универсальная реализация RelayCommand для биндинга действий в XAML
│
├── docs/                          # Проектная документация
│   └── PROJECT_STRUCTURE.md       # Описание структуры проекта и архитектурных соглашений
│
├── Models/                        # Доменные сущности, состояние и данные (Domain / State)
│   ├── PetState.cs                # Состояние питомца (настроение PetMood, энергия, счетчики)
│   └── DialoguePhrase.cs          # Модель реплик диалога и условий их отображения
│
├── Services/                      # Бизнес-логика, внешние API, фоновые сервисы
│   ├── IPetBehaviorService.cs     # Контракт сервиса поведения и диалогов питомца
│   ├── PetBehaviorService.cs      # Реализация автономного поведения и смены настроений
│   ├── IAudioService.cs           # Контракт сервиса воспроизведения звуков и озвучки
│   ├── IVoiceRecognitionService.cs # Контракт захвата микрофона и распознавания речи
│   └── VoiceRecognitionService.cs  # Реализация ASR на базе Whisper.net и NAudio (VAD + 16kHz)
│
├── ViewModels/                    # Презентационная логика (MVVM)
│   ├── BaseViewModel.cs           # Базовый класс с реализацией INotifyPropertyChanged
│   └── MainViewModel.cs           # ViewModel главного окна (биндинги диалогов, реакций и команд)
│
├── Views/                         # Представления (XAML) и UI-компоненты
│   ├── Controls/                  # Пользовательские элементы управления (UserControl)
│   ├── MainWindow.xaml            # Главное окно оверлея (разметка, стили, анимации, биндинги)
│   └── MainWindow.xaml.cs         # Code-behind окна (исключительно оконные события: DragMove, координаты)
│
├── App.xaml / App.xaml.cs         # Точка входа приложения, жизненный цикл и глобальные ресурсы
├── AssemblyInfo.cs                # Метаданные сборки
├── CapriPet.csproj                # Файл конфигурации сборки .NET SDK
├── LICENSE                        # Лицензия проекта (MIT)
└── .gitignore                     # Правила исключения временных файлов и кэша сборки
```

## Назначение слоев и правила размещения кода

### 1. `Models/` (Модели данных)
- **Что хранить:** чистые структуры данных, `record`, `class`, перечисления (`enum`), DTO и классы конфигурации.
- **Правило:** модели не должны зависеть от UI (`System.Windows`), ViewModels или сервисов. Они представляют состояние приложения.

### 2. `ViewModels/` (Презентационная логика)
- **Что хранить:** классы моделей представления, наследующие `BaseViewModel`.
- **Правило:** связывают данные из `Models` и `Services` с элементами отображения в XAML через Data Binding. Здесь объявляются свойства с уведомлением об изменении (`OnPropertyChanged` / `SetProperty`) и команды (`ICommand`). ViewModels не должны напрямую манипулировать элементами управления окна.

### 3. `Commands/` (Команды)
- **Что хранить:** реализации `ICommand` (например, `RelayCommand`, `AsyncRelayCommand`).
- **Правило:** обеспечивают слабую связность между нажатиями кнопок в UI и методами в ViewModel.

### 4. `Services/` (Сервисы бизнес-логики)
- **Что хранить:** фоновые задачи, работу со звуком (`IAudioService`), распознавание речи, глобальные хуки клавиатуры/мыши, интеграции с системным треем, таймеры поведения (`IPetBehaviorService`).
- **Правило:** логика оформляется через интерфейсы (`I...`) для обеспечения слабой связанности и удобства тестирования/замены реализаций.

### 5. `Views/` (Пользовательский интерфейс)
- **Что хранить:** XAML-разметку окон и пользовательских элементов управления (`UserControl`).
- **Правило:** в файлах `*.xaml.cs` (code-behind) допускается только код, связанный непосредственно с платформенным поведением окна (например, вызов `DragMove()`, расчет экранных координат). Вся логика взаимодействия реализуется через DataContext и команды.

### 6. `Assets/` (Ресурсы)
- **Что хранить:** медиа-файлы (спрайты в `Sprites/`, аудиофайлы в `Audio/`, иконки в `Icons/`).
- **Правило:** файлы ресурсов подключаются в проект через `.csproj` со свойством `Resource` или `Content`.
